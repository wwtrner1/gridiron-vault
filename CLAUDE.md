## What this is

GridIronVault (capital I — the brand changed from "Grid1ronVault" in October 2026; lowercase ids such as `grid1ronvault.*` localStorage keys, drag types and the old `gridi1ronvault` address keep the old spelling so nothing breaks) — a flag football playbook studio. Logos live in `public/brand/` (icon, horizontal and stacked lockups, shield); app icons and favicons are PNGs rendered from the icon. Coaches draw plays on an SVG canvas, organise them into playbooks, plan games in a spreadsheet-style Season Grid, and export PNG/PDF/wristband cards. Vite + React 19 SPA, a single Netlify Function as the API, Netlify Database (Postgres) via Drizzle, Netlify Identity for auth. Deployed on Netlify. (Formerly "NextPlay"/"Snapline" — those names still appear in localStorage keys; don't rename the keys or existing users lose their data.)

## Architecture

### Local-first data, cloud when signed in
- `src/lib/store.ts` is the app's source of truth: a hand-rolled external store (`useSyncExternalStore`) persisted to `localStorage` under `snapline.workspace.v1`, holding plays, playbooks and call sheets.
- Every save writes to the local store first, then — only if signed in — calls the API and replaces the local record with the server copy (`toStoredPlay`, `remote: true`). Signed-out coaches keep working entirely in the browser. See the save flow in `src/pages/Builder.tsx`.
- `store.mergeRemotePlays` reconciles server rows by `updatedAt` (newer wins).
- A refused workspace write (storage full, or a private window that blocks it) keeps the session in memory and fires `onStorageFailed` once; `components/StorageWatch.tsx` (mounted in `App.tsx`) toasts the coach so new work isn't lost quietly with the tab (the wording follows the sign-in state at the moment of the failure, read through a ref). `tests/storage-full.spec.ts` covers it with the workspace key refusing every write: the signed-out and signed-in words, the plays still on screen from memory, nothing on the disk, and no second toast for a second refused write.
- No signal: `api.ts` turns a failed `fetch` into `OFFLINE_MESSAGE` (`isOffline`). A signed-in save that can't reach the account keeps `remote` and is marked `unsynced` (Vault pill "Not synced yet"; `markUnsynced` for scene-only updates from the Vault and Griddy cards). `PlaySync` (`src/lib/playSync.ts`, mounted in `App.tsx`) sends unsynced plays on sign-in and on the window `online` event, then on sign-in pulls the account's plays (`pullPlays`, so a new device's Playbooks, Wristbands and Call Sheet have them before the Vault is opened; `tests/play-pull.spec.ts`), and fires `PLAY_ID_EVENT` when a browser play gets its account id so an open Designer follows it instead of saving a copy. `PlaybookSync` and `SheetSync` also push on `online`; the Call Sheet's Save button goes through `pushSheetNow` (same push, so the two never both create a sheet), and Griddy's call-sheet card only writes the store. A play or playbook delete shows a toast with Undo (`ToastAction` in `lib/toast.tsx`; a toast with a button stays 8 s): the record goes back into the store (and its playbooks, at the same spot); an account copy is already in the account's trash, so it goes back up as a new play (`remote: false, unsynced: true` + `syncPlays`) or a new playbook (`cloudId` cleared). Deletes go through `deleteFromAccount` (`src/lib/pendingDeletes.ts`): with no signal the account id waits in `grid1ronvault.deletes.v1`, the store's `mergeRemote*` skip it so it can't come back, and `PlaySync` flushes the list first.
- Other per-browser stores: `tier.ts` (`nextplay.tier.v1`), `track.ts` (`nextplay.events.v1`), `autofill.ts` (`nextplay.autofill.v1`).

### API (`netlify/functions/api.ts`)
- One function mounted at `/api/*`, hand-routed by path segments `[resource, id, action]`. Resources: `me`, `plays` (incl. `POST plays/:id/copy`), `playbooks` (incl. `POST playbooks/:id/plays`), `call-sheets`, `ai` (`griddy`, `assistant`, `photo`; see Griddy below).
- `PUT /api/plays/:id` only writes the fields it is sent (`sanitisePlayPatch`), so scene-only updates from bulk edits keep the play's name and tags.
- Auth comes from `getUser()` (`@netlify/identity`) server-side; writes are scoped with `ownerId = me.id` in the `WHERE` clause. `ensureProfile` upserts a `profiles` row on first write.
- Errors are returned as `{ error }` with coach-facing wording; `src/lib/api.ts` throws `data.error` as an `ApiError` (with `status`) so the UI can toast it directly; a 502/504 without our JSON reads "didn't get an answer in time". For a catch that can also see library or script errors (exports, Griddy), show `coachError(e, fallback)`, which passes only `ApiError` and offline wording through.
- `track()` beacons to `/api/events`; the function stores the three known events for signed-in coaches (`events` table) and answers 204 to everything else.
- Client wrapper: `src/lib/api.ts`. Add a resource by adding a branch in the function and a method on `api`.

### Griddy (the coaching agent)
- Griddy replaced the Play assistant. A coach talks to him from any page: `GriddyProvider` (`src/components/Griddy.tsx`, mounted in `App.tsx`) holds one conversation for the visit, a floating launcher opens the panel everywhere except `/signin` and `/build`, and the Designer has `GriddyComposer variant="bar"` in place of the old assistant bar. The panel, composer and quick picks live in `GriddyPanel.tsx`, loaded (via `lazyPage`) the first time the panel opens; `send()` imports `bulkEdit`, `assistant`, `explain` and `griddyVault` on demand, so none of Griddy's play code is in the first download. Import his name and limits from `lib/griddyLimits.ts` in anything loaded at start (a value import of `lib/griddy.ts` drags the tools and their imports into the entry chunk). The Designer registers its field with `useGriddyDrawer` so "Yes, draw it" drops a play straight on it.
- `src/lib/griddy.ts` is the contract shared by browser and function: turn/action types, `GRIDDY_LIMITS` (defined in `griddyLimits.ts`, re-exported here), the five tools (`draw_play`, `import_plays`, `show_plays`, `bulk_edit`, `build_call_sheet`) and the cached system prompt. Per-message context (page, open play, the coach's terms, a list of Vault plays and playbooks) goes after the coach's latest message as a `role: "system"` message, so the cached prefix stays stable.
- `POST /api/ai/griddy` → `netlify/ai/griddy.ts`: checks the browser-held history, rebuilds it as Claude messages (every `tool_use` gets a `tool_result` saying what the coach did with the card), calls `converse()` and validates every action (`cleanRead` in `netlify/ai/reads.ts`; `show_plays` ids must be in the Vault list sent). Thinking blocks are never replayed, so history edits can't invalidate them.
- Bulk import: Griddy only splits a dump into `{ name, call }` entries. The import card then reads each play through `POST /api/ai/assistant` with `bulk: true` (Haiku, three at a time) and saves with `savePlays` in `src/lib/griddyVault.ts`, which also files them in a named playbook. Nothing is drawn or saved without the coach confirming on a card.
- Bulk edits (`bulk_edit`): Griddy only describes the change and the scope (whole Vault, a playbook by name, or listed plays, optionally narrowed by `filter`: play type, tag or formation). Changes: `style` (any Style card look on players, lines or text, picked by `where`: letter, current color, side, line style; values held to `STYLE_LIMITS`), `wristband` (`bold` is the Designer's Wristband bold via `wristbandBold`, `sideline` thickens routes; the card also sets the Wristbands page preset via `chooseBandPreset`), `field` (the field a play is drawn on: half, full, redzone, flag 30×70, blank; sets `scene.view` and `fieldView` and keeps route depths in yards; `filter.field` picks plays by their current field, and the Vault list has a field column), `meta` (type and tags), `file` (add to or move between playbooks), plus the older recolor, swap (optional new color), route_color, clear_letters, remove_text and mirror (which also swaps Right/Left in the name and formation). The server checks open-ended changes with `cleanOpenChange`/`cleanFilter`; a filter that doesn't parse drops the change rather than widening it. GRIDDY_SYSTEM tells Griddy never to call a style change impossible. `only` narrows a player change to one current color ("the green Xs"), matched by `sameColor`; the context sends `looks` (every letter and color in the Vault) and each play's playbooks so Griddy can name real fills. `src/lib/bulkEdit.ts` works out the plays and players it touches (pure, so the card's preview and the write use the same code); node ids are kept so routes stay attached. The card writes through the store and `api.updatePlay`, edits the open Designer play live via the drawer's `onEdit` (so its next save doesn't overwrite the change), and Undo restores only plays still as the edit left them.
- Renaming (`bulk_edit` op `rename`): while the coach's recent messages mention names, routes or diagrams, the Vault list in the context gets a routes-drawn column from `routeSummary` (`src/lib/explain.ts`, e.g. "X go · Y corner 10") and every row a number `n`; Griddy sends `{ n, name, formation? }` entries and `toActions` maps `n` back to the Vault id (unknown rows are dropped). `planBulkEdit` skips plays whose name already matches; the card shows `old → new` and Undo restores names. GRIDDY_SYSTEM tells Griddy to use the closest tool rather than answer "I can't". A rejected API key (401/403) now reads "Griddy is offline while we fix a problem on our side" in `claude.ts` instead of "couldn't read that".
- Coverage (`NEEDS_COVERAGE` in `Griddy.tsx`): while the coach's recent messages talk coverages, each Vault row gets a `beats` column ("5v5: 1 rush · Cover 2, …" or "none") from `checkAll` (lazy-loaded `lib/coverage`, cached per play `updatedAt`). GRIDDY_SYSTEM tells Griddy to answer "what beats Cover 2?" and coverage-based call sheets from it, never from guesswork.
- Call sheets (`build_call_sheet`): Griddy picks Vault plays per situation; the card builds a Season Grid with `gridFromPlays` from `src/lib/sheet.ts` (the same helpers the Season Grid page uses), every row linked to its play. `tests/griddy-sheet-import.spec.ts` covers this card (sections, Drop, an id not in the Vault ignored, Create the call sheet, Open Call Sheet landing on the linked rows) and the import card (Draw all through the bulk reader, a failed call shown in coach words, a renamed play, Save to Vault filed in a named playbook on the account).
- Quick picks (`QUICK_PICKS` in `GriddyPanel.tsx`) type a starter into the panel's box via the provider's `prefill`; they never send. A whiteboard photo attached in chat goes to `/upload` (router state `{ photo }`) for the existing photo review. `tests/griddy-panel.spec.ts` covers the panel (the launcher, the hello and starters, a starter typed into the box and never sent, Clear, a text file of calls landing in the box and an empty one refused, Enter sending and Shift+Enter a new line, the quick picks row and Start a new conversation, Escape with focus back on the launcher, the conversation kept on the next screen, no launcher on `/signin` and the Designer's bar instead).
- Models live in `MODELS` in `netlify/ai/claude.ts` (official `@anthropic-ai/sdk`; since 2026-10-28 calls go through Netlify AI Gateway, which injects `ANTHROPIC_API_KEY`/`ANTHROPIC_BASE_URL` at runtime while no key is set on the site; setting our own `ANTHROPIC_API_KEY` in Netlify overrides it). Griddy's conversation uses server-side refusal fallbacks (`fallbacks: "default"`) and low effort.
- Timeouts and refunds: every Claude call carries a 50 s `AbortSignal` (`DEADLINE_MS` in `claude.ts`, under Netlify's 60 s function limit), which reads "Griddy took too long…" (504). AI routes wrap the call in `chargedOnSuccess` (`api.ts`), which refunds the `spend` count when it ends in an `AiError`.
- Limits: server daily caps in `DAILY_AI` (`api.ts`: `assistant` counts Griddy messages and single reads, `import` counts bulk-read plays); monthly plan limits in `plan.ts` (`assistantCalls`, gated by `gateAi`, counted per browser in `aiUsage.ts`).
- Griddy's face (`GriddyMascot.tsx`) is the GridIronVault "G" with the football, in a lighter cyan: `public/brand/griddy.webp` (the badge loads the 96 px `griddy-96.webp`). The badge does the Griddy (a CSS bob and tilt) when a play he drew is saved. Don't use NFL footage or a real player's likeness for him.

### Database
- Schema: `db/schema.ts` (Drizzle, Postgres). Client: `db/index.ts` uses `drizzle-orm/netlify-db` — no connection string in code.
- Migrations live in `netlify/database/migrations/` (drizzle-kit output dir). Change the schema, then `npm run db:generate`; never hand-edit generated migrations/snapshots.
- `plays.scene` is JSONB holding the whole editor document; its shape is the `Scene` type, not a DB schema.

### Play editor / scene model
- `src/lib/types.ts` defines `Scene` (`version: 2`, fixed `CANVAS_W`×`CANVAS_H` = 1040×660, `losY`, `nodes`) and the node union: `player | path | shape | text`, all sharing transform fields (x/y/rotation/scale/z/groupId/locked/hidden).
- One scene drives everything: the editor (`components/PlayCanvas.tsx`), thumbnails (`PlayThumb`), and exports. `PlayThumb lazy` (Starters, Vault grid) draws a diagram only when it nears the screen; `decorative` hides one inside a button that already names the play. ### Billing (Stripe)
- Sideline exports cap at 86 DPI (`maxDpi`, lowest DPI chip is 86). Browser prints on Sideline are blurred and tiled with a watermark: `useFreePrint` (`lib/guard.ts`, mounted in `App.tsx`) sets `data-free-print` on `<html>` and the `@media print` block at the end of `global.css` does the rest. Deterrent only.
- A subscription that Stripe reports `past_due` or `unpaid` drops the coach to Sideline immediately (`PAYING` in `applySubscription` is only `active`/`trialing`); a paid retry restores the plan. Meanwhile the subscription id is kept and `profiles.paymentFailedAt` is set, `GET /api/me` returns `paymentFailed`, and `PaymentBanner` (in `Shell`) asks the coach to update the card in Stripe's portal; Pause is hidden.
- A fully refunded or disputed Season Pass (`charge.refunded`, `charge.dispute.created` → `revokeSeason`) ends at once: `planEndsAt` cleared, Sideline unless a subscription runs. A past_due subscription keeps `stripeSubscriptionId`, so `startCheckout` already refuses a second plan.
- Checkout turns on Stripe Tax (`automatic_tax`, billing address required, `customer_update` for returning customers); prices are made `tax_behavior: exclusive` by `stripe:setup`. Stripe only charges tax where a registration is added in the Dashboard; Checkout fails if Tax has no head-office address or a price has no tax behavior (set Settings, Tax, default tax behavior).
- Subscription webhooks re-retrieve the subscription from Stripe before applying it (out-of-order safe).
- `netlify/billing/stripe.ts`: Checkout (`POST /api/billing/checkout {offer}`), the customer portal (`POST /api/billing/portal`) and the webhook (`POST /api/billing/webhook`, public, signature-checked, handled before the sign-in and phone checks). Off until `STRIPE_SECRET_KEY` and `STRIPE_PRICES` are set; `GET /api/me` returns `billing` and the browser (`useBilling`, `goToBilling` in `tier.ts`) then sends plan buttons to Stripe instead of the beta switcher. Back from Checkout (`/account?billing=success`) the Account page says it is confirming the payment, asks `/api/me` every 2 s for up to 20 s until the webhook has set the plan (toast "You're on …"), and otherwise says the plan hasn't reached the account yet and names support (`tests/billing-return.spec.ts`).
- `npm run stripe:setup` (`scripts/stripe-setup.ts`) creates the products, prices (lookup keys `gv_<offer>`), customer portal settings and the webhook endpoint in whichever mode the key is in, and prints `STRIPE_PRICES`/`STRIPE_WEBHOOK_SECRET`; `-- --check` changes nothing, `-- --live` is required for a live key. `npm run stripe:probe` POSTs an unsigned body to the live webhook: 404 means billing is still off on that deploy, 400 means the keys reached it. Support address is `SUPPORT_EMAIL` in `src/lib/site.ts`.
- Pause instead of cancel: `POST /api/billing/pause {months}` (1, 2, 3 or 6; monthly plans only) sets Stripe `pause_collection` (`behavior: "void"`, `resumes_at`), `POST /api/billing/resume` clears it. A paused subscription drops the coach to Sideline and records `profiles.pausedUntil` but keeps `stripeSubscriptionId`, so they can resume early; Stripe lifts the pause on its own and the webhook restores the plan. `GET /api/me` returns `subscribed` and `pausedUntil` for `components/PausePlan.tsx` on the Account page. `tests/account-state.spec.ts` covers what `/api/me` tells the pages (mocked): a trial's days left and "ends today" in the side menu, the failed-payment banner with Update card (a Stripe refusal in its words, then the portal), the switched-off banner appearing as soon as a call answers `account_suspended`, and the Account page's Pause instead of cancel (a refusal, a pause, Resume my plan now, the plan pill following) and Manage billing.
- `STRIPE_PRICES` is JSON mapping `solo_month`, `solo_year`, `season`, `crew_month`, `crew_year`, `program_month`, `program_year`, `founding` to Stripe price ids; amounts live in Stripe. Also `STRIPE_WEBHOOK_SECRET`. The webhook is the only writer of `profiles.plan` for paying coaches (`stripeCustomerId`, `stripeSubscriptionId`, `planEndsAt`). A Season Pass is a one-time payment that sets `planEndsAt` four months out; `planState` drops it to Sideline after that when no subscription is behind it. `founding` is refused unless the account's plan is still `beta`.

### Export

### Coverage check and Coverage report (our answer to HotRead's Auto-Coach)
- `lib/coverage.ts` (pure) runs a coach's own drawn play against a live defense: receivers follow their drawn routes (`buildTimeline` tracks, which now carry `pathId`), zone defenders drop to their landmark and squeeze the nearest receiver (deep ones read later and stay on top; underneath ones carry at most `UNDER_DEPTH`), man defenders trail their man by `TRAIL`, rushers chase the QB. Man defenders line up on their man (cushion off, a step inside) and lose a beat in traffic (`RUB`: another receiver or man defender close by, which is what makes Mesh beat man); underneath zone defenders wall at depth and pass a receiver off (`PASS_OFF`) once he's past them. It works in yards (`yardScale`: across and up the field differ per view). `npm run coverage:concepts` (scripts/coverage-concepts.ts) checks that Smash, Flood, Mesh, Four Verts and Stick still beat the coverages they were built for in 11-man, 7v7 and 5v5; run it after any tuning. At the throw (`THROW_AT` by format) each receiver's space to the nearest cover defender makes him open (≥2.5 yd), tight or covered; `wins` needs someone open past the line before the rush gets home, `grade` is the one color per look.
- Looks per format (`formatOf`: a line or 9+ means 11-man, 6+ means 7v7): 11-man is the Defense library's 4-3 with each `COVERAGES` entry, 5v5 the `FLAG_LOOKS` (rusher on the league rush line), 7v7 its own seven-man layouts with no rush. Stock looks are scaled from half-field units to the play's field.
- `components/CoverageCheck.tsx` (Designer: Extras → "Coverage check", and "Run it against a defense" in Run play): look chips colored by grade, animated field with read-order badges and open/tight/covered rings, Ball out 1.6/default/3.0 s, the Read/Player/Route/Space/Status table, and "Show … on the field" (sets the Vs defense overlay). `/coverage` (`pages/Coverage.tsx`) runs every pass play in the Vault or one playbook and lists the best three calls per look. It is a teaching model; the copy says so. Keep the two screens on the same `checkAll`.

## Conventions

- **Styling:** plain CSS. Design tokens live only in `src/styles/tokens.css`; `global.css` consumes them. **The Grid1ron Design canvas (https://claude.ai/artifact/6gfQeotou5QDBHLrA4P8vn) is the source of truth** for every screen, color, font and size; the GridIronVault design system artifact is a reference only, and the canvas wins where they differ. Change a value in tokens, not in component styles. Fonts: Saira Condensed, Barlow, IBM Plex Mono, self-hosted as latin woff2 files in `public/fonts/` (`src/styles/fonts.css` for the app, `public/fonts/fonts.css` for the static guides; keep the two in step). `index.html` preloads the body and headline weights. Nothing loads from Google Fonts any more, so the CSP allows styles and fonts from our origin only.
- **Colors in scene data** are hex constants in `types.ts` (`PALETTE`, `FIRST_READ`, `STROKE_WEIGHTS`) and `presets.ts` (position colors: Q black · C cyan · X blue · Y red · Z green · H orange · S light purple), since they are serialised into saved plays and exports.
- **Copy:** user-facing text speaks to "coach", is specific and action-oriented, and never leaks raw library/server errors. `docs/copy-audit.md` records the standard and past fixes.
- **Accessibility:** WCAG 2.1 AA. Reuse `Modal` (focus trap, Escape, `aria-labelledby`), `Tooltip` (`aria-describedby`) and `Panel` (`aria-expanded`) rather than building new ones. A full-screen dialog that can't be a `Modal` (Run play, the Coverage check, Field controls, the print preview bar, a player's Run play on `/team`) calls `useDialogFocus(panel, onClose, initial?)` from `lib/dialogFocus.ts`, the same hook `Modal` uses: focus moves in on open (an `autoFocus` box keeps it; the opener is read during the first render, before that box commits), Tab stays inside, Escape closes it in the capture phase so nothing behind sees the key, and focus returns to the opener if it is still on the page. `onClose` is read through a ref, so an inline `onClose` never re-runs the focus move (which used to pull focus out of Field controls' boxes after every keystroke). The Designer's Extras menu hands focus to its own button before an item unmounts, so a dialog opened from it returns focus there. `tests/dialog-focus.spec.ts` covers all of it. Never `window.confirm`: a delete gets a toast with Undo (`ToastAction`) where it can be put back, and `components/Confirm.tsx` (an in-app box with Cancel, used by Draw together's delete and the family texts' new link) where it can't. `docs/accessibility.md` is the record of what was fixed and why; `tests/accessibility.spec.ts` keeps axe green, so run it after touching labels, names or dialogs.
- **Analytics:** only three events exist on purpose (`play_created`, `call_sheet_opened`, `play_exported`) — don't add more without a reason.
- **CSP:** `netlify.toml` sets a strict Content-Security-Policy (`script-src 'self'`, `connect-src 'self'`, `font-src 'self'`). New third-party scripts, fetches or fonts must be added there or they'll be blocked in production.
- `NETLIFY_NEXT_PLUGIN_SKIP=true` in `netlify.toml` is intentional (a leftover account-level Next.js plugin); keep it.
- Work lands in small phase-labelled PRs (e.g. "Phase 1: …") merged into `main`.
