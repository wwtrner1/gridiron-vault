This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Names and addresses

- Canonical domain: **https://gridiron-vault.com** (Netlify DNS; www redirects to the apex). Use it for every absolute URL (Open Graph, Identity email templates, redirects). `gridiron-vault.netlify.app` only forwards to it.
- Repo slug: **wwtrner1/gridiron-vault**.

- Saved plays live in `localStorage`, which belongs to one origin. `public/handoff.js` (loaded first from `index.html`) and `old-address/move.js` forward plays from the older addresses to the apex in `#carry=…`, and `src/components/CarryOver.tsx` merges them (newer wins; never `gotrue.*`).

## What this is

GridIronVault (capital I — the brand changed from "Grid1ronVault" in October 2026; lowercase ids such as `grid1ronvault.*` localStorage keys, drag types and the old `gridi1ronvault` address keep the old spelling so nothing breaks) — a flag football playbook studio. Logos live in `public/brand/` (icon, horizontal and stacked lockups, shield); app icons and favicons are PNGs rendered from the icon. Coaches draw plays on an SVG canvas, organise them into playbooks, plan games in a spreadsheet-style Season Grid, and export PNG/PDF/wristband cards. Vite + React 19 SPA, a single Netlify Function as the API, Netlify Database (Postgres) via Drizzle, Netlify Identity for auth. Deployed on Netlify. (Formerly "NextPlay"/"Snapline" — those names still appear in localStorage keys; don't rename the keys or existing users lose their data.)

## Commands

```bash
npm ci                 # install
npm run dev            # Vite dev server (frontend only — /api and Identity are not served)
netlify dev            # full stack locally: Vite + functions + Identity (needs Netlify CLI + linked site)
npm run build          # production build to dist/
npx tsc -p .           # typecheck (tsconfig has noEmit; there is no lint or test script)
npm run db:generate    # drizzle-kit: generate a migration from db/schema.ts
npm run griddy:live    # Griddy against the real Claude API with a fixture Vault (needs ANTHROPIC_API_KEY; --dry scores ideal replies, --runs N, --only flip,sheet)
```

There is no test suite, linter, or formatter configured. `npx tsc -p .` and `npm run build` are the checks to run before pushing; the `Checks` workflow (`.github/workflows/ci.yml`) runs both on every PR.

## Architecture

### Local-first data, cloud when signed in
- `src/lib/store.ts` is the app's source of truth: a hand-rolled external store (`useSyncExternalStore`) persisted to `localStorage` under `snapline.workspace.v1`, holding plays, playbooks and call sheets.
- Every save writes to the local store first, then — only if signed in — calls the API and replaces the local record with the server copy (`toStoredPlay`, `remote: true`). Signed-out coaches keep working entirely in the browser. See the save flow in `src/pages/Builder.tsx`.
- `store.mergeRemotePlays` reconciles server rows by `updatedAt` (newer wins).
- Other per-browser stores: `tier.ts` (`nextplay.tier.v1`), `track.ts` (`nextplay.events.v1`), `autofill.ts` (`nextplay.autofill.v1`).

### API (`netlify/functions/api.ts`)
- One function mounted at `/api/*`, hand-routed by path segments `[resource, id, action]`. Resources: `me`, `plays` (incl. `POST plays/:id/copy`), `playbooks` (incl. `POST playbooks/:id/plays`), `call-sheets`, `ai` (`griddy`, `assistant`, `photo`; see Griddy below).
- `PUT /api/plays/:id` only writes the fields it is sent (`sanitisePlayPatch`), so scene-only updates from bulk edits keep the play's name and tags.
- Auth comes from `getUser()` (`@netlify/identity`) server-side; writes are scoped with `ownerId = me.id` in the `WHERE` clause. `ensureProfile` upserts a `profiles` row on first write.
- Errors are returned as `{ error }` with coach-facing wording; `src/lib/api.ts` throws `data.error` so the UI can toast it directly.
- `track()` beacons to `/api/events`; the function stores the three known events for signed-in coaches (`events` table) and answers 204 to everything else.
- Client wrapper: `src/lib/api.ts`. Add a resource by adding a branch in the function and a method on `api`.

### Griddy (the coaching agent)
- Griddy replaced the Play assistant. A coach talks to him from any page: `GriddyProvider` (`src/components/Griddy.tsx`, mounted in `App.tsx`) holds one conversation for the visit, a floating launcher opens the panel everywhere except `/signin` and `/build`, and the Designer has `GriddyComposer variant="bar"` in place of the old assistant bar. The Designer registers its field with `useGriddyDrawer` so "Yes, draw it" drops a play straight on it.
- `src/lib/griddy.ts` is the contract shared by browser and function: turn/action types, `GRIDDY_LIMITS`, the five tools (`draw_play`, `import_plays`, `show_plays`, `bulk_edit`, `build_call_sheet`) and the cached system prompt. Per-message context (page, open play, the coach's terms, a list of Vault plays and playbooks) goes after the coach's latest message as a `role: "system"` message, so the cached prefix stays stable.
- `POST /api/ai/griddy` → `netlify/ai/griddy.ts`: checks the browser-held history, rebuilds it as Claude messages (every `tool_use` gets a `tool_result` saying what the coach did with the card), calls `converse()` and validates every action (`cleanRead` in `netlify/ai/reads.ts`; `show_plays` ids must be in the Vault list sent). Thinking blocks are never replayed, so history edits can't invalidate them.
- Bulk import: Griddy only splits a dump into `{ name, call }` entries. The import card then reads each play through `POST /api/ai/assistant` with `bulk: true` (Haiku, three at a time) and saves with `savePlays` in `src/lib/griddyVault.ts`, which also files them in a named playbook. Nothing is drawn or saved without the coach confirming on a card.
- Bulk edits (`bulk_edit`): Griddy only describes the change and the scope (whole Vault, a playbook by name, or listed plays, optionally narrowed by `filter`: play type, tag or formation). Changes: `style` (any Style card look on players, lines or text, picked by `where`: letter, current color, side, line style; values held to `STYLE_LIMITS`), `wristband` (`bold` is the Designer's Wristband bold via `wristbandBold`, `sideline` thickens routes; the card also sets the Wristbands page preset via `chooseBandPreset`), `field` (the field a play is drawn on: half, full, redzone, flag 30×70, blank; sets `scene.view` and `fieldView` and keeps route depths in yards; `filter.field` picks plays by their current field, and the Vault list has a field column), `meta` (type and tags), `file` (add to or move between playbooks), plus the older recolor, swap (optional new color), route_color, clear_letters, remove_text and mirror (which also swaps Right/Left in the name and formation). The server checks open-ended changes with `cleanOpenChange`/`cleanFilter`; a filter that doesn't parse drops the change rather than widening it. GRIDDY_SYSTEM tells Griddy never to call a style change impossible. `only` narrows a player change to one current color ("the green Xs"), matched by `sameColor`; the context sends `looks` (every letter and color in the Vault) and each play's playbooks so Griddy can name real fills. `src/lib/bulkEdit.ts` works out the plays and players it touches (pure, so the card's preview and the write use the same code); node ids are kept so routes stay attached. The card writes through the store and `api.updatePlay`, edits the open Designer play live via the drawer's `onEdit` (so its next save doesn't overwrite the change), and Undo restores only plays still as the edit left them.
- Renaming (`bulk_edit` op `rename`): while the coach's recent messages mention names, routes or diagrams, the Vault list in the context gets a routes-drawn column from `routeSummary` (`src/lib/explain.ts`, e.g. "X go · Y corner 10") and every row a number `n`; Griddy sends `{ n, name, formation? }` entries and `toActions` maps `n` back to the Vault id (unknown rows are dropped). `planBulkEdit` skips plays whose name already matches; the card shows `old → new` and Undo restores names. GRIDDY_SYSTEM tells Griddy to use the closest tool rather than answer "I can't". A rejected API key (401/403) now reads "Griddy is offline while we fix a problem on our side" in `claude.ts` instead of "couldn't read that".
- Call sheets (`build_call_sheet`): Griddy picks Vault plays per situation; the card builds a Season Grid with `gridFromPlays` from `src/lib/sheet.ts` (the same helpers the Season Grid page uses), every row linked to its play.
- Quick picks (`QUICK_PICKS` in `Griddy.tsx`) type a starter into the panel's box via the provider's `prefill`; they never send. A whiteboard photo attached in chat goes to `/upload` (router state `{ photo }`) for the existing photo review.
- Models live in `MODELS` in `netlify/ai/claude.ts` (official `@anthropic-ai/sdk`; since 2026-10-28 calls go through Netlify AI Gateway, which injects `ANTHROPIC_API_KEY`/`ANTHROPIC_BASE_URL` at runtime while no key is set on the site; setting our own `ANTHROPIC_API_KEY` in Netlify overrides it). Griddy's conversation uses server-side refusal fallbacks (`fallbacks: "default"`) and low effort.
- Limits: server daily caps in `DAILY_AI` (`api.ts`: `assistant` counts Griddy messages and single reads, `import` counts bulk-read plays); monthly plan limits in `plan.ts` (`assistantCalls`, gated by `gateAi`, counted per browser in `aiUsage.ts`).
- Griddy's face (`GriddyMascot.tsx`) is the GridIronVault "G" with the football, in a lighter cyan: `public/brand/griddy.webp`. The badge does the Griddy (a CSS bob and tilt) when a play he drew is saved. Don't use NFL footage or a real player's likeness for him.

### Database
- Schema: `db/schema.ts` (Drizzle, Postgres). Client: `db/index.ts` uses `drizzle-orm/netlify-db` — no connection string in code.
- Migrations live in `netlify/database/migrations/` (drizzle-kit output dir). Change the schema, then `npm run db:generate`; never hand-edit generated migrations/snapshots.
- `plays.scene` is JSONB holding the whole editor document; its shape is the `Scene` type, not a DB schema.

### Play editor / scene model
- `src/lib/types.ts` defines `Scene` (`version: 2`, fixed `CANVAS_W`×`CANVAS_H` = 1040×660, `losY`, `nodes`) and the node union: `player | path | shape | text`, all sharing transform fields (x/y/rotation/scale/z/groupId/locked/hidden).
- One scene drives everything: the editor (`components/PlayCanvas.tsx`), thumbnails (`PlayThumb`), and exports. Shared SVG rendering is in `lib/render.tsx` (`NodeLayer`, `MarkerDefs`) and `lib/field.tsx` (field backgrounds per `FieldView`).
- `lib/scene.ts` — pure scene ops (selection, align/distribute/flip, cloning, node factories). Auto-connect paths store `fromId`/`toId`; call `reconcileConnections(scene)` before saving so they stay glued to their tokens.
- `lib/geometry.ts` — transforms and path-data math. `lib/tools.ts` — tool/mode definitions and export sizes. `lib/presets.ts` — position token colors and formation presets. `lib/starters.ts` — the 56 starter plays built as real scene data.
- New Play setup (`components/PlaySetup.tsx`, `lib/playSetup.ts`): a fresh `/build` asks for name, personnel (the `personnel.ts` list, 11-man first), formation, field and playbook, then `setupScene` lines the personnel up (`setupPlayers`; 8-/6-man trim the 11-man set; defensive personnel get the closest `FRONTS` front against a scout offense). Last picks and the on/off switch live in `grid1ronvault.newplay.v1` (Extras → "New play setup"); the playbook is filed on the first save (`fileNewPlay`). Navigate with router state `{ skipSetup: true }` to open a blank Designer (Griddy does), `{ setup: true }` to force it.
- Side panels: on tablets and up the tools rail and the Selection/Play panel tuck against their edges from slim edge tabs (`.dz-edge` in `designer.css`); Ctrl+\ (or the field menu) hides or shows both. Remembered in `grid1ronvault.panels.v1` (the right panel only on wide screens, where it docks). Call `showRail()`, not `setRailOpen(true)`, so a tucked rail comes back too. The field refits through the stage's ResizeObserver.
- First read: at most one `PathNode` per play has `firstRead: true`, always drawn in `FIRST_READ` (cyan-2) via `lineColor()`.
- Floating tools (`components/FloatingToolbar.tsx`): a draggable, collapsible mini-bar over the field (Select, Route, Dashed, Block, Text; 1st read / 2nd read / Checkdown / Defense colors; weights). It is a sibling of `.builder-stage` inside `.dz-stage-wrap`, never inside the canvas, so it can't swallow drawing. Picks restyle the selected lines or set the next line, through the same Builder state as the Style card. Its color row (the `PALETTE` swatches plus the full `ColorPicker`) colors whatever is selected (lines, player fills with their letters, labels) or the next line (`pickColor` in `Builder.tsx`), and its head carries Undo and Redo. Its spot, open state and dock live in `grid1ronvault.floatbar.v1`; Home on the grip or the dock button puts it back in the corner.

- Top bar: brand, play name, Prev/Next, the work tabs, then zoom, Fit, Details, Run play, Export, Save and **Extras** (one drop-down, `#dz-more-menu`, sections Edit, Field, Play, Go to, Help). Undo/Redo, Clean up, Route depths, the field select, Field controls, Vs defense, Upload, More tools and Back to the Vault live in Extras now; a dot on the button shows while depths or Vs defense is on. Below 760px Details/Run/Export move into it too (`is-wide-dup`), and below 900px the work tabs do (`is-tabs-dup`).

### Work tabs
- `components/WorkTabs.tsx` + `lib/workTabs.ts`: Designer · Playbook · Wristbands · Call Sheet, in the Designer's top bar (`tone="dark"`), under the Shell top bar on Playbooks, Wristbands and the Call Sheet (Shell's `tabs` prop). They are plain links carrying one context in `grid1ronvault.worktabs.v1` (last play and playbook from the Designer, last Call Sheet from the Call Sheet and Wristbands): Playbook opens `/playbooks?book=`, Wristbands `?source=book:<id>`, Call Sheet `/grid?sheet=` (last sheet, else the one with most calls from the playbook). In the Designer a tab saves unsaved changes first (`openFromTree`).

### Plans and gating
- `src/lib/plan.ts` owns every entitlement (`TIERS`, `gateSave`, `gateGrid`, `gateSize`, `gateSheets`, `gateTool`, `gateShare`, `cappedDpi`). UI and export both read gates from here — add new limits here, not in components. A `Gate` carries user-facing `reason`/`cta`.
- The account's plan lives in `profiles.plan` (default `beta`) and the API enforces what it can see: Vault size and public copies (`plays`), Season Grids (`call-sheets`), and monthly Griddy/photo use (`ai`), refusing with `{ code: "plan_limit" }` and the gate's own wording. `tier.ts` mirrors it in the browser (`syncPlan` after sign-in; `choosePlan` for the Account/Pricing pickers). During beta coaches switch plans themselves via `PUT /api/me/plan`; set `PLAN_SELF_SERVE=false` when billing takes over. Export sizes, sheets and locked tools happen in the browser, so they're client-side gates only.
- `lib/guard.ts` (`useCaptureGuard`) deters screenshots on paid diagrams; the real protection is watermark + DPI cap in `export.tsx`/`plan.ts`.

### Billing (Stripe)
- Sideline exports cap at 86 DPI (`maxDpi`, lowest DPI chip is 86). Browser prints on Sideline are blurred and tiled with a watermark: `useFreePrint` (`lib/guard.ts`, mounted in `App.tsx`) sets `data-free-print` on `<html>` and the `@media print` block at the end of `global.css` does the rest. Deterrent only.
- A subscription that Stripe reports `past_due` or `unpaid` drops the coach to Sideline immediately (`PAYING` in `applySubscription` is only `active`/`trialing`); a paid retry restores the plan.
- `netlify/billing/stripe.ts`: Checkout (`POST /api/billing/checkout {offer}`), the customer portal (`POST /api/billing/portal`) and the webhook (`POST /api/billing/webhook`, public, signature-checked, handled before the sign-in and phone checks). Off until `STRIPE_SECRET_KEY` and `STRIPE_PRICES` are set; `GET /api/me` returns `billing` and the browser (`useBilling`, `goToBilling` in `tier.ts`) then sends plan buttons to Stripe instead of the beta switcher.
- `STRIPE_PRICES` is JSON mapping `solo_month`, `solo_year`, `season`, `crew_month`, `crew_year`, `program_month`, `program_year`, `founding` to Stripe price ids; amounts live in Stripe. Also `STRIPE_WEBHOOK_SECRET`. The webhook is the only writer of `profiles.plan` for paying coaches (`stripeCustomerId`, `stripeSubscriptionId`, `planEndsAt`). A Season Pass is a one-time payment that sets `planEndsAt` four months out; `planState` drops it to Sideline after that when no subscription is behind it. `founding` is refused unless the account's plan is still `beta`.

### Playbook sync
- Playbooks are local-first like plays but `src/lib/playbookSync.ts` (`PlaybookSync`, mounted in `App.tsx`) copies them to the account while signed in: sign-in pulls `GET /api/playbooks` (playbooks plus ordered member ids) and `store.mergeRemotePlaybooks` adds new ones and takes a cloud copy newer than the local one; every store change pushes a moment later (`POST /api/playbooks` once, then `PUT /api/playbooks/:id` with `playIds` replacing the whole list); `store.removePlaybook` deletes it from the account (clearing the local workspace does not). A local playbook keeps its own id and records the account's as `cloudId`; only UUID play ids (plays already on the account) are sent. Don't call `api.createPlaybook` from feature code, just write through the store. A play saved to the account gets a new id: use `store.replacePlayId` so it stays in its playbooks.

### Playbook tree
- `components/PlaybookTree.tsx` is the folder tree of playbooks (plus Unfiled) with their plays: counts, P/R/D/S badges, `+` for a new play in a folder (`/build?book=<id>`; `save()` in the Builder files the new play there), a new-playbook field, find box (over 8 plays), drag a play onto a folder to add it, and WAI-ARIA tree keys (arrows, Home/End, Enter, `*`). It sits in the Shell side menu and on the Designer's Plays tab (folder icon, `RAIL_GROUPS.plays`), where opening a play saves unsaved changes first. Open folders are remembered in `grid1ronvault.tree.v1` (`lib/treeState.ts`); it reads and writes only through the store, so playbook sync carries every change.

### Phone check (Twilio Verify)
- `netlify/security/phone.ts`: every account has a verified mobile and a new device needs a texted code ("Confirm this device", `PhoneGate.tsx`). The check is on only while `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` and `TWILIO_VERIFY_SID` are all set (and never on Deploy Previews). To switch it off, delete `TWILIO_VERIFY_SID` in Netlify and redeploy; coaches then sign in with no code. Env changes only reach the function on a new deploy.
- Twilio 20003 / 401 ("invalid username") means the Account SID and Auth Token in Netlify don't match the Twilio account (usually a rotated token); 21608 means the Twilio account is still a trial. Both show coaches "Texting codes is down on our side". Fix the keys in Netlify, re-add `TWILIO_VERIFY_SID`, redeploy, then test a code.

### Owner (All-Access Master)
- `netlify/security/owner.ts` decides who the owner is: confirmed Identity emails in its built-in list plus the `OWNER_EMAILS` env var (comma-separated). `api.ts` puts `owner` on the `Session`; `planOf` returns `TIERS.master` for the owner (no limits), `ensureProfile` keeps their `profiles.plan` at `master`, `choosePlan` refuses `master` and refuses the owner, and `spend` never cuts the owner off (it still counts). `master` is not in `PUBLIC_TIERS`. `session()` asks Identity's admin API whether the owner's email is confirmed when `getUser()` came back without the stamp (it falls back to bare token claims when Identity is unreachable); `GET /api/me` returns `ownerHint` to a listed address that was refused, so the reason is visible. Never gate owner powers on anything the browser sends.

### Owner console (`/admin`)
- `pages/Admin.tsx` (tabs in `pages/admin/`) is hidden from non-owners by `useOwner()`, but the real gate is `me.owner` on `/api/admin/*` (`adminRoute` in `api.ts`; anyone else gets the plain 404). Logic lives in `netlify/admin/` (`admin.ts` users, CSV, audit, `WATCH` thresholds for the abuse flags; `visits.ts` visitor counter). Owner views of one coach's data and every change go through `audit()` into the append-only `audit_log`.
- Signup history = Identity `admin.listUsers` ∪ `profiles` ∪ `account_ledger` (written by `deleteAccount`: email, hashed phone, no plays). `profiles.lastActiveAt` is touched by `ensureProfile` at most every five minutes.
- Recovery (`netlify/admin/recovery.ts`): the coach's own `DELETE` of a play, playbook or call sheet first copies the row into `trash` (`keepInTrash`, 30 days, a playbook also keeps its member play ids); the owner opens a coach (`GET admin/users/:id`), restores from `trash` (`POST admin/trash/:id/restore`, optionally into another coach's account), downloads everything as JSON, or sets a plan (never `master`). Account deletion deliberately skips the trash (privacy promise) and only writes `account_ledger`.
- Visitor counter: `useVisitCounter` (`lib/visits.ts`) beacons `POST /api/visit` (public route, before the phone gate) per page view and every 30 s of visible time; rows in `visits` hold no IP, cookie or user id (visitor = hash of device id + day). DNT/GPC send nothing; the owner's own visits and `/admin` are skipped. This is separate from the three `track()` events.

- New coaches and the trial: with `TRIAL_SIGNUPS=on` a new account starts on `trial` (Head Coach tools for `TRIAL_DAYS`, `profiles.trialEndsAt`) and `planState()` in `api.ts` drops it to Sideline (`free`) when it ends; with it off, new accounts join as `beta` as before. One trial per person: `startTrial` folds the email (+tags, Gmail dots) and refuses throwaway domains and any email or phone seen in `trial_claims` or `account_ledger`; `verifiedPhone` takes the trial back if the number was already used or is internet-only (Twilio Lookup, fails open; `TRIAL_BLOCK_VOIP=off` skips it). The helpers are in `netlify/security/trial.ts`. While trials are on, `PUT /api/me/plan` only allows stepping down to Sideline (paid plans open with billing). Sideline caps: 8 plays, 1 playbook (`gatePlaybook`, client and `POST /api/playbooks`), 1 Season Grid, 5 Griddy messages a month, no photo reviews; plays over a cap are kept, not deleted.

### Export
`lib/export.tsx`: `PrintDiagram` / `sceneToSvg` is the source for every export and print preview. `lib/printLook.ts` frames a diagram for its printed size (`fit: "play"` crops to the players and routes; `weight` makes lines and tokens heavier, `"auto"` picks it from the size so a 1-inch wristband box doesn't print hairlines; auto tokens never drop below 0.09 in and print as plain dots under 0.11 in, and route tags/text grow to at least 5.5 pt). `frameScene` returns `ptPerUnit`, which turns on print-only drawing: white rings on tokens and white casings under routes (`NodeLayer print`), and a field that leaves off markings too small to read and keeps the lite LOS at half route weight. Zoom never cuts the play off (`keepPlay` slides or grows the box back over every player, curve control point, route tag and text). Yard lines in every field view (`yardLines` in `lib/field.tsx`) run every 5 yards out from the line of scrimmage and carry their distance, so a route's depth reads off the card; print field `"yards"` (the card default) draws just those lines and the LOS. `placeDiagram` draws into jsPDF as vector paths via `svg2pdf.js` (lazy-loaded) when `gateVector` allows, otherwise a PNG at the plan's DPI. `playsToPdf` and the export preview share `pdfSlots`. Wristband cards are `lib/wristbands.ts` (card size: `BAND_SIZES` lists real wristband windows by maker plus custom; columns × rows; numbering incl. "A1, A2" card spots; header/border text with `{role}` `{card}` `{source}` `{count}`, paper or one card per page, cut marks) with `components/BandPreview.tsx` as the drag-to-reorder preview; `tightBoxes` (via `lettersFit` in `printLook.ts`) warns which boxes will print as plain dots, and every sheet carries a 1-inch scale bar so a coach can catch "Fit to page" printing; settings persist in `grid1ronvault.wristbands.v1`. One-click styles are `BAND_PRESETS` (Wristbands page: "Sideline 2×4", "Wristband bold") and `EXPORT_PRESETS` in `ExportDialog.tsx`; a preset is just a partial set of the same settings, so add new ones there. Drawings scale with the box: auto token and route weights are capped by the diagram's printed height (`autoWeight(unitsAcross, inches, heightIn)`: tokens at most 20% of the box height down to 0.07 in, routes down to 1.1 pt), and `playBox` ignores anything dragged off the canvas so a stray node can't shrink the whole play. `boxCheck` (`lib/wristbands.ts`, `READABLE_BOX`) tells the Wristbands page when a box is too short to read and offers the densest grid that is readable. `PrintLook` also takes Playmaker-style `zoom`, `icons`, `lines` and `dots`. PowerPoint export is `lib/pptxExport.ts` (`pptxgenjs`, lazy-loaded); `lib/pptx.ts` is PowerPoint *import*. UI in `components/ExportDialog.tsx`.

### Scans and PDFs (Upload)
- `/upload` sends PDFs, scanned pages, single photos and several images at once to `components/ScanReview.tsx`. PDF pages are drawn to canvases in the browser by PDF.js (`lib/scanPdf.ts`, lazy-loaded; its wasm decoders and fonts are served from `/pdfjs/` by the `pdfjsAssets` plugin in `vite.config.ts`, which is why the CSP has `'wasm-unsafe-eval'`). Nothing uploaded is stored: only JPEGs go to the API, and nothing saves until the coach presses Save.
- `POST /api/ai/scan` (`SCAN_TOOL`/`cleanBoxes` in `lib/scan.ts`) finds each play's box on a page: it needs a photo review left this month but doesn't use one, capped by `DAILY_AI.scan`. Each kept play is cropped at full resolution and read by the existing `POST /api/ai/photo` (one photo review each); a single photo with one play goes straight to `PhotoReview`. "Check and fix" opens `PhotoReview` with `check` (no second read). Printed titles and notes become the play name and Coaching notes; plays file into a new playbook named after the file.

### Player links and Griddy Quiz
- A coach shares a playbook from Playbooks → Players (`components/PlayerLink.tsx`): the browser sends a frozen snapshot (`toSnapshot`, `cleanSnapshot` and `SHARE_LIMITS` in `src/lib/share.ts`, re-checked by the function) to `POST /api/shares`, which stores it in `playbook_shares` behind a random token (one link per playbook, keyed by the coach's own playbook id in `source`; sharing again refreshes the plays and keeps the address). Gated by `gateShare`. The snapshot is deliberately a copy, so local-only playbooks and plays share the same way and a player never sees the coach's Vault.
- Players open `/team/:token` (`pages/Team.tsx`, no sign-in, no Shell, no Griddy launcher): `GET /api/shares/:token` and `POST /api/shares/:token/results` are the only public routes and sit before the sign-in and phone checks in `api.ts`. The page reuses `assignmentsFor` (their job spotlighted) and `lib/runPlay.ts` (animation). The Griddy Quiz (`lib/quiz.ts`, pure) builds "which route does the X run?" and "which play is this?" questions from the snapshot, so a coach writes nothing; scores go to `quiz_results` (capped per link, newest kept) and show in the coach's dialog. The letter and name a player picks are remembered in `grid1ronvault.team.v1`.

### Front Office (league and program sharing)
- `/front-office` (`pages/FrontOffice.tsx`, styles `frontOffice.css`) lets a director run one organisation (`organizations`, one per owner), invite coaches by email (`org_members`: `invited` until the coach signs in with that address and joins, then `active` with `userId`) and share frozen playbook snapshots (`org_shares`, same `Snapshot` as player links, `cleanSnapshot(raw, "A Front Office playbook")`; one entry per `source` playbook, sharing again replaces it). No email is sent: the invite shows when the coach signs in.
- Routes live in `netlify/front-office/orgs.ts` (`/api/orgs`, `/api/org-members/:id`, `/api/org-shares/:id`), after the sign-in and phone checks. A shared playbook opens only for the director or an `active` member (anyone else gets 404), and every answer is `private, no-store`: never put a public cache header on Front Office data. Types and `parseEmails`/`cloneSharedPlay` are in `src/lib/frontOffice.ts`.
- Running one is gated by `gateFrontOffice` and `Tier.orgSeats` (Staff 3, Program 12, beta 12, master unlimited; invited + joined coaches count); joining is free on every plan. A director who drops a plan keeps existing shares readable but can't invite or share more.
- Clone is browser-side: `cloneSharedPlay` gives every play a new id and `savePlays` files them in a new playbook ("Name (Org)"), checked against the coach's own `gateSave` first. It only ever adds; the master and the coach's existing plays are never written. Deleting a director's account removes their organisation; members keep their clones.

### Team hub (Front Office tabs)
- `/front-office?tab=…&org=…&team=…` adds tabs beside "Playbooks & coaches" (`TABS` in `pages/FrontOffice.tsx`; tab components in `pages/frontOffice/`). An organisation holds `teams` (director creates them, picks each staff: `coachIds` = `org_members` ids, or `allCoaches`). The director sees every team; an active member coach sees only teams whose staff they're on (`onStaff` in `netlify/front-office/hub.ts`); anyone else gets the same 404 as a missing team.
- Roster (`team_players`, `RosterTab.tsx`): names and jersey are columns, everything else (`PlayerInfo`: contacts, up to 3 guardians with an "OK to text" flag, medical notes) is `info` JSONB cleaned by `cleanPlayer` in `src/lib/teamHub.ts`. Spreadsheet paste/CSV import (`playersFromTable`, loose heading match), CSV download (`rosterCsv`), print contact sheet. Minors' contacts: staff only, every answer `private, no-store`, never a public route.
- Depth chart (`depth_charts`, one row per team and unit: offense, defense, special; `DepthTab.tsx`): spots (`DepthSlot`: label, playbook letter, player ids 1st string first) start from `DEPTH_PRESETS` (flag 5/7, 11-man), drag or arrow to reorder, autosave per unit; `cleanDepth` drops ids not on the team. "Starters to Assignments" writes each lettered spot's starter into the `roster.ts` letter roster.
- Schedule (`hub_events`, `ScheduleTab.tsx`): games, practices, meetings per team, or `teamId` null for the whole Front Office (director only). Month grid and list, won-lost record (`record`), weekly repeat on create (up to 26 more), `.ics` download (`scheduleIcs`), cancel without deleting, scores, and a game's Call Sheet (`sheetId`, a local sheet id) opens that Call Sheet. Writes need staff rights on the event's team (`mayWrite`).
- Messages (`hub_messages`, `MessagesTab.tsx`): a coaches' board (`staff`, per team or the whole Front Office) and announcements to players and families (`family`). Recipients are always computed on the server: emails from the roster (`familyContacts`), texts only to numbers in `text_signups`. Families opt themselves in on the team's public `/join/:token` page (`pages/Join.tsx`, `netlify/front-office/texts.ts`, link and list in `FamilyTexts.tsx` on the Messages tab; `teams.joinToken`, `consentWording`/`CONSENT_VERSION` in `teamHub.ts`), because A2P 10DLC carriers reject consent a coach ticks for someone else; the roster's "OK to text" now only feeds the coach's own `sms:` links. Every server text starts "GridIronVault - Team:" (`teamText`). `GET|POST /api/join/:token` is public (before the sign-in checks, capped per team per day). Server sending is off until set up (`netlify/front-office/send.ts`: Resend via `RESEND_API_KEY` + `HUB_EMAIL_FROM`; Twilio Messages via `TEAM_SMS=on` + `TWILIO_MESSAGING_SID` or `TWILIO_FROM`); until then the browser offers mailto (Bcc) / `sms:` links and copy buttons. Daily caps in `MESSAGE_LIMITS`. Setup steps: `docs/team-messaging-setup.md`.
- Files (`hub_folders`, `hub_files`, `FilesTab.tsx`, `netlify/front-office/files.ts`): folders per team or for the whole Front Office (director only), bytes in the private `team-files` Netlify Blobs store under `<orgId>/<fileId>`. Upload sends the raw file as the body (name in `X-File-Name`), allowed types `FILE_TYPES`, 5 MB each, 500 MB per Front Office. Downloads are always `attachment` + `nosniff`, staff only. Deleting a row does not delete its blob: folder/file/team routes, closing a Front Office and `deleteAccount` read keys first (`orgFileKeys`) and call `dropBlobs` after.
- Routes: `GET|POST /api/hub/:orgId/folders`, `PUT|DELETE /api/hub-folders/:id`, `POST /api/hub-folders/:id/files`, `GET|DELETE /api/hub-files/:id`, `GET|POST /api/hub/:orgId/messages`, `DELETE /api/hub-messages/:id`, `GET|POST /api/hub/:orgId/events`, `PUT|DELETE /api/hub-events/:id`, `GET|PUT /api/teams/:id/depth`, `GET /api/hub/:orgId`, `POST /api/teams`, `PUT|DELETE /api/teams/:id`, `GET|POST /api/teams/:id/players`, `PUT|DELETE /api/team-players/:id`, after the sign-in and phone checks. Teams cascade with the organisation.

### My team (solo roster)
- `/roster` (`pages/MyTeam.tsx`) gives a coach without a Front Office one team's roster and depth chart. It renders the Front Office's own `RosterTab` and `DepthTab` over a `TeamSource` (`src/lib/teamSource.ts`): `hubSource(teamId)` is the API (the Front Office default), `localSource()` keeps the team in `grid1ronvault.myteam.v1` (this browser only, checked with the same `cleanPlayer`/`cleanDepth`). Add new roster or depth features to the tabs and the `TeamSource` type, not to one page.
- The depth chart's "Starters to Assignments" fills the `roster.ts` letter roster; the Assignments roster offers My team's names (picking one fills the jersey). A downloaded CSV imports into a Front Office team.

### Field Controls
- One panel above the field (`components/FieldControls.tsx`, the Designer's "Field controls" button; "More" on phones) holds snap to grid (size), snap lines to players and its radius (the drawing bar's Snap), hash marks (high school, college, pro, none), yard-line contrast (soft, standard, high) and the league rule lines. `lib/fieldPrefs.ts` keeps them in `grid1ronvault.field.v1` (per browser, like the other prefs); `FieldBackground` reads hashes and contrast from it unless given props, so the canvas, thumbnails, Run play and every export match. Flag views never draw hashes; the grid never prints. Export starts with rule lines on when they're on in the Designer.

### League rule lines and talking points
- `lib/rules.ts` holds coach-editable rule distances (`RuleLines`: rush line yards, no-run zone yards, and `set`, the rule set id) and the rule sets (`RULE_PRESETS`/`ruleSet`: NFL FLAG 5-on-5, 7-on-7 passing, Rush line only, Tackle 11, each saying players a side, blocking, QB run, runs, rushing, midfield no-run zone, seven on the line), saved in `grid1ronvault.rules.v1`. The rush line sits on the defense's side of the ball (rushers start behind it); the flag field also gets a no-run zone before midfield when the set has one (`fieldMarks` in `lib/field.tsx` knows where the goal line and midfield are).
- Play drawer (the Designer's right panel, Play tab, `Inspector.tsx`): **Play intel** (name, formation, type, personnel, field, notes, labels), **Opponent front** (`OpponentFront.tsx`: a stock 11-man front + coverage or a 5-on-5 flag look, or a saved defense, shown through the Vs defense overlay; stock looks are stored as `look:…` overlay values and built by `lookScene` in `lib/overlay.ts`, never saved into the play) and **Rules check** (`RulesCheck.tsx` over `checkRules` in `lib/ruleCheck.ts`). The check is pure and reads geometry, not notes: offense count, T-capped blocks, ball carriers (QB solid line across the line with no exchange; handoffs/tosses/reverses found by paths meeting behind the line, only on plays not marked pass), no-run zones from the ball spot, rusher start depth (solid defender lines reaching the line, including the overlay's), and motion (one man, never toward the line). "Show me on the field" selects the offending nodes.
- Changing the field (`convertField` in `lib/fieldConvert.ts`, used by the top-bar select and the drawer) keeps routes true to the yard: depth rescales from the LOS by yard spacing, width maps sideline to sideline, and the play slides back onto the canvas if needed. Griddy's bulk `field` change goes through the same `convertField` (in `editScene`), and its Undo puts the old field, line of scrimmage and drawing back. The measurements it needs (`fieldInset`, `unitsPerYard`) live in `lib/fieldUnits.ts` so the API function can load them without React. `RuleLinesLayer` (`lib/field.tsx`) draws them over the field in the Designer (switched on in Field Controls or the Rules check), and on prints when `PrintLook.rules` is on (switch in the Export dialog and on the Wristbands page; prints use the saved distances whether or not the Designer overlay is on); the no-run zone shades from the goal line, so it shows on Red zone and Flag views. Distances are editable on purpose: leagues and federations differ, so don't hard-code a rulebook as fact.
- `lib/explain.ts` (`explainPlay`) turns a scene into plain-language talking points per player; the Inspector's "Write the talking points for me" appends them to Coaching notes.

## Conventions

- **Styling:** plain CSS. Design tokens live only in `src/styles/tokens.css`; `global.css` consumes them. **The Grid1ron Design canvas (https://claude.ai/artifact/6gfQeotou5QDBHLrA4P8vn) is the source of truth** for every screen, color, font and size; the GridIronVault design system artifact is a reference only, and the canvas wins where they differ. Change a value in tokens, not in component styles. Fonts: Saira Condensed, Barlow, IBM Plex Mono (Google Fonts, loaded in `index.html`).
- **Colors in scene data** are hex constants in `types.ts` (`PALETTE`, `FIRST_READ`, `STROKE_WEIGHTS`) and `presets.ts` (position colors: Q black · C cyan · X blue · Y red · Z green · H orange · S light purple), since they are serialised into saved plays and exports.
- **Copy:** user-facing text speaks to "coach", is specific and action-oriented, and never leaks raw library/server errors. `docs/copy-audit.md` records the standard and past fixes.
- **Accessibility:** WCAG 2.1 AA. Reuse `Modal` (focus trap, Escape, `aria-labelledby`), `Tooltip` (`aria-describedby`) and `Panel` (`aria-expanded`) rather than building new ones. `docs/accessibility.md` is the record of what was fixed and why.
- **Analytics:** only three events exist on purpose (`play_created`, `call_sheet_opened`, `play_exported`) — don't add more without a reason.
- **CSP:** `netlify.toml` sets a strict Content-Security-Policy (`script-src 'self'`, `connect-src 'self'`, fonts only from Google). New third-party scripts, fetches or fonts must be added there or they'll be blocked in production.
- `NETLIFY_NEXT_PLUGIN_SKIP=true` in `netlify.toml` is intentional (a leftover account-level Next.js plugin); keep it.
- Work lands in small phase-labelled PRs (e.g. "Phase 1: …") merged into `main`.
